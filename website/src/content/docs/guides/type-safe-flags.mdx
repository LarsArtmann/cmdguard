## Struct-Tag-Driven Flags

cmdguard replaces Cobra's `Flags().GetString("name")` pattern with typed structs. A field becomes a flag when it carries a `flag` tag, and cmdguard handles registration, parsing, and validation. `NewCommand` takes the flags struct by value and hands it to the handler as the third parameter.

```go
package main

import (
	"context"
	"fmt"
	"os"
	"strings"

	"github.com/larsartmann/cmdguard/v5/pkg/cmdguard/v5"
)

// AppConfig holds the root flags. Root flags are persistent by default.
type AppConfig struct {
	Verbose bool   `flag:"verbose" short:"v" default:"false" help:"Enable verbose output"`
	Config  string `flag:"config" help:"Path to the config file" local:"true"`
}

// GreetFlags holds flags that exist only on the greet command.
type GreetFlags struct {
	Name  string `flag:"name"  short:"n" default:"World" help:"Name to greet"`
	Loud  bool   `flag:"loud"  default:"false" help:"Uppercase the greeting"`
	Times int    `flag:"times" default:"1" help:"Repetitions" validate:"min=1,max=100"`
}

func main() {
	cli, err := v5.NewCLI[AppConfig]("demo", "A greeting CLI", AppConfig{})
	if err != nil {
		fmt.Fprintf(os.Stderr, "error: %v\n", err)
		os.Exit(1)
	}

	b := v5.NewBuilder(cli)
	v5.Add(b, "greet", GreetFlags{},
		func(_ context.Context, _ *AppConfig, f GreetFlags) error {
			msg := fmt.Sprintf("Hello, %s!", f.Name)
			if f.Loud {
				msg = strings.ToUpper(msg)
			}
			for range f.Times {
				fmt.Println(msg)
			}
			return nil
		},
		v5.WithShort("Greet someone"),
		v5.WithExample("demo greet --name Alice --times 2"),
	)
	if err := b.Build(); err != nil {
		fmt.Fprintf(os.Stderr, "error: %v\n", err)
		os.Exit(1)
	}

	cli.ExecuteAndExit(context.Background())
}
```

## Tag Reference

| Tag        | Effect                                                                      | Example                    |
| ---------- | --------------------------------------------------------------------------- | -------------------------- |
| `flag`     | Flag name. A field registers as a flag only when this tag is present        | `flag:"name"`              |
| `short`    | Single-character shorthand                                                  | `short:"n"`                |
| `default`  | Default value (the zero value when absent)                                  | `default:"World"`          |
| `help`     | Help text                                                                   | `help:"Name to greet"`     |
| `env`      | Environment variable fallback (prefixable with `WithEnvPrefix`)             | `env:"DB_HOST"`            |
| `required` | Must be set by flag or env var. Bool tag; a tag default does not satisfy it | `required:"true"`          |
| `count`    | Counting flag (`-vvv` becomes 3). The field must be `int`                   | `count:"true"`             |
| `local`    | Owning command only, not inherited by subcommands. Bool tag                 | `local:"true"`             |
| `hidden`   | Excluded from `--help`, fully functional. Bool tag                          | `hidden:"true"`            |
| `values`   | Comma-separated allowed values, enforced as an enum                         | `values:"dev,prod"`        |
| `validate` | Rule list, enforced after parsing and against the default at construction   | `validate:"min=1,max=100"` |
| `prompt`   | Prompt text shown when the flag is missing (needs the prompts sub-module)   | `prompt:"Your name?"`      |
| `secret`   | Redacts the value in `config explain`, `describe`, docs, and schemas        | `secret:"true"`            |

## Flag Scopes

A flag lives in exactly one of three scopes.

| Where the field lives               | Scope                                                  |
| ----------------------------------- | ------------------------------------------------------ |
| Root `T` struct, plain              | Persistent: inherited by every subcommand              |
| Root `T` struct with `local:"true"` | Root only, not inherited by subcommands                |
| A command's own `F` struct          | That command only, never inherited, rejected elsewhere |

F-struct flags are registered on the command's own flag set, so `demo greet --build` fails with "unknown flag" unless the `greet` struct declares `build`. That is the designed behavior, not a limitation. A subcommand that needs a root-local flag opts in with `cli.RegisterLocalCommandFlags(cobraCmd)`.

## Precedence

An explicit flag beats an environment variable, which beats a config-file value, which beats the tag default. Config-file values are loaded before flags register and rewrite the tag defaults, which is what gives them their position in the chain.

## Per-Command Flag Structs

`Command[T, F]` has one type parameter for the root config and one for the command's own flags. Different commands can use entirely different flag structs:

```go
type DeployFlags struct {
	Env     string        `flag:"env"     short:"e" required:"true" help:"Target environment"`
	Timeout time.Duration `flag:"timeout" default:"5m" help:"Deployment timeout"`
}

deploy, err := v5.NewCommand("deploy", DeployFlags{},
	func(ctx context.Context, cfg *AppConfig, f DeployFlags) error {
		return runDeploy(ctx, cfg, f.Env, f.Timeout)
	},
	v5.WithShort("Deploy the application"),
)
```

`NewCommand` returns a `Command[T, F]` value and an error, never a pointer and never a panic. A command with no own flags uses `v5.NoFlags{}`, and `cmdguard.ArgsFromContext(ctx)` returns its positional arguments.

## Counting Flags

The `count:"true"` tag implements verbosity ladders. The field must be an `int`, and counting flags must not reuse a root config flag name.

```go
type Flags struct {
	Verbose int `flag:"verbose" short:"v" count:"true" help:"Verbosity level"`
}

// $ demo -vvv  ->  f.Verbose == 3
```

## Validation Tags

- `values:"a,b,c"` rejects anything outside the list with `ErrInvalidEnum`.
- `validate:"min=1,max=100"` compares lengths on string fields and numeric bounds on numbers.
- `validate:"minlen=3,maxlen=20"` is the explicit length form for strings.
- `validate:"dmin=10s,dmax=1m"` compares durations on `Duration` and `time.Duration` fields.
- Built-in validators also include `email`, `url`, `nonempty`, and `regex=^pattern$`.
- Register your own with `v5.RegisterValidator`; see [Custom Value Types](/guides/custom-types/).
- Defaults are validated at construction: a `default` outside the `values` list or bounds fails `NewCLI` with `ErrInvalidFlagDefault`, so a bad default never reaches users.

`required:"true"` runs after parsing. It is satisfied only by an explicit flag or a set environment variable, which keeps a default from silently masking a missing credential.

## Environment Variables

The `env` tag is the middle rung of the precedence chain. `WithEnvPrefix` prepends a prefix to every `env` tag lookup:

```go
type DBFlags struct {
	Host     string `flag:"host"     env:"DB_HOST"     default:"localhost"`
	Port     int    `flag:"port"     env:"DB_PORT"     default:"5432"`
	Password string `flag:"password" env:"DB_PASSWORD" secret:"true"`
}

cli, err := v5.NewCLI[AppConfig]("myapp", "My app", AppConfig{},
	v5.WithEnvPrefix("MYAPP_"), // reads MYAPP_DB_HOST, MYAPP_DB_PORT
)
```

If the `env` tag already names a prefixed variable, `WithEnvPrefix` prefixes it again: the prefix is applied to the tag value verbatim, not to the variable's base name.

## Built-in Value Types

cmdguard ships validated field types that parse at flag time instead of at first use:

| Type        | Parses                                     |
| ----------- | ------------------------------------------ |
| `Duration`  | `30s`, `5m`, `1h30m`                       |
| `Enum`      | One value of an allowed list               |
| `LogLevel`  | debug, info, warn, error                   |
| `LogFormat` | text, json                                 |
| `URL`       | Absolute URL with scheme and host          |
| `Email`     | RFC 5322 address                           |
| `Port`      | 1 to 65535, numeric or named               |
| `HostPort`  | `host:port`                                |
| `FilePath`  | Cleaned path, optional existence check     |

`time.Duration` and `time.Time` are supported directly as well.

## Nested Config Structs

`ParseFlagTags` recurses into nested structs, so flags can be organized into groups while keeping flat flag names. Nested fields without their own `flag` tag are walked; registered value types stay atomic and are never descended into.

```go
type AppConfig struct {
	Verbose bool `flag:"verbose" short:"v" default:"false"`
	DB      DatabaseConfig
}

type DatabaseConfig struct {
	Host string `flag:"db-host" env:"DB_HOST" default:"localhost"`
	Port int    `flag:"db-port" env:"DB_PORT" default:"5432"`
}
```
