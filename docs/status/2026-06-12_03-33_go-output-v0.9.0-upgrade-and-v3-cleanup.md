## e) WHAT WE SHOULD IMPROVE

### Self-Review Findings

1. **Forgot to update docs initially** — README.md, QUICKSTART.md, and taskctl/README.md still had references to removed APIs (`v2.FormatTable`, `v2.ParseOutputFormat`). Caught in self-review, fixed.

2. **go.mod indirect deps** — `go-output/enum v0.7.0` and `go-output/escape v0.7.0` remain as transitive deps. Not our fault (upstream sub-modules reference v0.7.0), but confusing. Should request upstream bump.

3. **Should have committed in smaller chunks** — All changes went in as one big batch. Better practice: commit dependency upgrade separately from API removal, separately from docs updates.

### Architecture Observations (from deep review)

4. **Middleware context propagation is the #1 architectural gap** — `next func() error` doesn't carry context. This means no middleware can implement timeouts, request-scoped values, or cancellation propagation. Simple fix: `next func(context.Context) error`.

5. **`config_setfield.go` cross-type conversions are fragile** — `time.Duration → Duration` special case at line 54-70 is a pattern that will repeat for every custom type. A `ConvertFrom(interface{})` interface would be cleaner.

6. **`type_handler_custom.go` default validation swallows errors** — The Duration default handler silently returns zero value on invalid defaults. Other handlers (bool/int) correctly return errors. This is inconsistent.

7. **Type models are well-designed** — The 7 custom types (URL, Email, Port, FilePath, HostPort, Duration, LogLevel) with their `MarshalText`/`UnmarshalText` + `IsEmpty` patterns are appropriate domain wrappers. Not duplicated by any library. The `textMarshal`/`textUnmarshal` generics are good enough — code gen would be over-engineering.

## g) Top #1 Question I Cannot Figure Out Myself

**Should we keep the `type OutputFormat = output.Format` alias or remove it entirely?**

Arguments for keeping:

- Convenience: users don't need to know about go-output's package path
- Stability: if go-output renames `Format`, we can adapt in one place
- The alias is zero-cost (compile-time only)

Arguments for removing:

- It obscures the real type origin — users see `v2.OutputFormat` and don't know it's `output.Format`
- It creates an import decision point: do users import go-output or not?
- All format constants (`FormatTable`, etc.) are already removed — the alias is the last remnant

**I lean toward keeping it** because it's the only type alias (not re-export) and costs nothing, but this is a judgment call about API philosophy.
