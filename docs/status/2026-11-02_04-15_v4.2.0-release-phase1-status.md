sibling requires into **unfetchable pseudo-versions**
(`v0.0.0-00010101000000-000000000000`) — the go-release "replace leak" poison.
v4.1.0/lint-v0.1.0 shipped real pins (verified from the tags). Fixed: root
go.mod restored to real pins (flightrecorder v0.1.0, glamour/spinner v0.2.0),
gate made **workspace-aware** (flake.nix), rule documented in AGENTS.md
gotchas + plan errata + TODO_LIST P6 (lint/v0.2.0 must restore
pin + version-scoped replace before its tag). The poisoned state never
reached a commit or tag.

## e) WHAT WE SHOULD IMPROVE

1. **Edit discipline** — build every edit from just-read text; after each
   multiedit on structured docs, grep the structure (headers/table shape), not
   just trust "Applied N edits".
2. **Load skills at the right time** — go-release governs the whole release
   pass; loading it at M05-start instead of mid-release would have prevented
   the poison detour entirely.
3. **Pre-commit file review** — `git status` + explicit paths before any
   `git add -A` on a machine with a parallel session and a commit daemon.
4. **Verify the surrounding surface, not just my work** — tag-triggered CI and
   pkg.go.dev were in the skill checklist and got skipped under time pressure.
5. **Toolchain alignment** — PATH `go` is 1.27.0, devShell/nix is 1.27.3;
   their tides diverge. Aligning (pin shell go or fix PATH) closes the flap
   mechanism instead of monitoring it.
6. **go vet gap** — the skill's Phase 4.1 includes `go vet`; check-all doesn't
   (that's plan M23). Should have run it ad hoc rather than defer silently.
7. **ADR for the semver judgment** — "behavior-changing enforcement ships as a
   minor with a migration note" is a deliberate exception worth an ADR, not
   just a CHANGELOG callout.
