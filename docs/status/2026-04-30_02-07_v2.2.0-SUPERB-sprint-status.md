## A) FULLY DONE ✅

### T1: TypeHandler Registry (type_handler.go — 471 lines)
- **What:** Unified the 3-way switch dispatch across `flags.go`, `flags_parse.go`, `config_setfield.go`, `config_parsing.go` into a single `TypeHandler` interface with `Register`, `Parse`, `Default` methods.
- **Impact:** ALL future type additions (env tags, config loading, custom types) now have ONE place to register. Extensible via `RegisterTypeHandler(reflect.Type, TypeHandler)`.
- **Files:** `type_handler.go` (new), `flags.go` (simplified), `flags_parse.go` (simplified), `config_setfield.go` (simplified), `config_parsing.go` (simplified)

### T2: Fix setStringField for Custom Types
- **What:** URL, Email, Port, FilePath, HostPort now work correctly via the TypeHandler registry instead of returning `ErrUnsupportedConversion`.
- **Impact:** 5 previously broken custom types in `SetField()` now parse correctly from strings.

### T3: Instance-Scoped Validator Registry
- **What:** `FlagRegistry` now has its own `validators` map. Instance validators are checked first, then global fallback. `RegisterFlagValidator(name, fn)` method on `FlagRegistry`.
- **Impact:** Concurrent tests no longer share mutable state. Two CLI instances can have different validators.

### T4: Fix Ptr[T] Function
- **What:** Changed `new(v)` to `&v`. Was returning zero-valued pointer instead of pointer to actual value.
- **Impact:** `Ptr(42)` now correctly returns `*int(42)` instead of `*int(0)`.

### T5: env:"VAR" Struct Tag
- **What:** Flags can specify `env:"DB_HOST"` tag. Priority chain: explicit flag → env var → default. `WithEnvPrefix[T]("APP_")` prepends prefix.
- **Impact:** 12-factor app compliance. Every serious CLI needs env var support.
- **Files:** `config.go` (FlagTag.Env field), `config_parsing.go` (parse env tag), `flags_parse.go` (env lookup), `cli.go` (wire envPrefix), `cli_options.go` (WithEnvPrefix option)

### T6: Subcommand Typo Suggestions
- **What:** `SuggestCommand(validCmds, input)` reuses existing Levenshtein distance. `wireSubcommandSuggestions()` auto-applied to parent commands.
- **Impact:** Users get "did you mean X?" instead of "unknown command" — the #1 Clap UX feature.

### T7: Signal Handling
- **What:** `WithSignalHandling[T]()` CLI option wraps `Execute()` with `signal.NotifyContext(ctx, SIGINT, SIGTERM)`.
- **Impact:** One-line opt-in for graceful shutdown on Ctrl+C.

### T8: go-output Integration
- **What:** `output.go` (224 lines) wraps `go-output` for 12 output formats. `OutputResult()`, `OutputTable()`, `OutputStyledTable()`, `ParseOutputFormat()`.
- **Impact:** Every cmdguard CLI can now output in table/JSON/CSV/TSV/Markdown/XML/D2/YAML/HTML/tree/Mermaid/DOT.

### T12: Counting Flags
- **What:** `count:"true"` struct tag maps to `pflag.CountP`. `-vvv` → 3.
- **Impact:** Logging CLIs with `-v`/`-vv`/`-vvv` verbosity levels.

### T15: $EDITOR Integration

- **Impact:** Config editing, commit message editing — the `click.edit()` pattern.

## D) TOTALLY FUCKED UP 💥

### T27: CLI in DI Scope — ATTEMPTED AND REVERTED
- **What happened:** Added `ProvideValue(cli.scope, cli)` in `initialize()` to register `*CLI[T]` in the DI scope.
- **Why it broke:** The scope integration tests use `Package[T]` which already registers CLI in the scope. Duplicate registration panics. Attempted fix with `Invoke[*CLI[T]]` check caused samber/do health check to hang (3+ minute timeout).
- **Current state:** REVERTED. CLI is NOT registered in DI scope.
- **Root cause:** samber/do/v2's health check system tries to health-check all registered services, and `*CLI[T]` doesn't implement `do.Healthchecker`. The health check hangs waiting for timeout.
- **Fix path:** Either implement `do.HealthcheckerWithContext` on `CLI[T]`, or use a separate "invoke-only" registration that bypasses health checks, or register lazily on first access.
