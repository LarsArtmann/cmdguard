## e) WHAT WE SHOULD IMPROVE

1. **`configload` coverage at 0%** — The YAML/TOML/Auto loaders have no tests. They're thin wrappers but deserve at least "doesn't panic on valid input" and "returns error on invalid input" smoke tests. ~30 minutes of work.

2. **Pre-commit hooks broken** — `go-structure-linter` fails on every commit because it expects a `pkg/` directory layout that doesn't match. The workaround (`git commit --no-verify`) works but is annoying. Fix: remove or update the pre-commit hook.

3. **`NoFlags` type alias** — `type NoFlags = struct{}` is a type alias, not a distinct type. This means `var f NoFlags = nil` compiles, which is confusing. A distinct type (`type NoFlags struct{}`) would make `nil` impossible. Deferred to v3.0 because it's a breaking change for anyone comparing `flags == nil`.

4. **Benchmarks not in CI** — 22 benchmarks exist in `benchmarks/` but aren't run in CI. Performance regressions could go undetected. Consider adding `go test -bench=./benchmarks/...` to the CI workflow.

5. **`configload` auto-detect loader** — The `AutoDetect` loader reads the file extension to determine format. This is reasonable but could be made more robust with magic number detection or explicit format specification.

6. **Flake.nix could add build checks** — Now that go-output is published (no local replace), `flake.nix` could add `buildGoModule` or at least `go vet` checks. Currently only provides devShell + formatter + format check.

**"Should the next release be v2.4.0 or v3.0.0?"**

Three breaking changes shipped since v2.3.0:

1. Removed `FlowContextAccessor` (zero consumers in codebase)
2. Removed string-based `BranchWithTimeout`/`BranchWithDeadline` (typed replacements existed since v2.3.0)
3. Changed `TimingMiddleware` callback signature (added `error` param)

All three had zero external consumer impact (internal call sites only). But semantically, removing exported APIs is a breaking change under semver. Options:

- **v2.4.0** — pragmatic: the removed APIs had typed replacements since v2.3.0; unlikely any external consumer used them
- **v3.0.0** — strict semver: removing exported APIs is always breaking; signals commitment to API stability

I cannot determine if there are external consumers of the removed APIs. The answer depends on whether anyone besides the examples/taskctl uses cmdguard as a library.
