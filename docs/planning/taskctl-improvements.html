taskctl Improvement Plan

Self-Critique: What's Wrong

Critical — Broken/Half-baked Implementations

  • inspect command is fake — declares WithExactArgs(1) but never reads the positional arg. Prints flags metadata, doesn't look up any task. BranchingFlowContext is shown but path is always empty because it only has meaning in nested subcommands.
  • Priority is a custom string type — cmdguard has a built-in v2.Enum type with values tag support. The custom parsePriority() function reimplements what v2.Enum already does. This is an anti-pattern for an example that should showcase the library.
  • OutputStyledTable not used — the stats command uses plain OutputTable even though we have OutputStyledTable available. Stats is the perfect place for styled output.

Important — Missing Feature Demonstrations

  • go-branded-id orphaned — was used in the deleted di-patterns example. Should either use it for Task IDs (demonstrates branded types) or remove from go.mod.
  • validate:"..." tag not shown — AddFlags has no validate tag. The library supports validate:"email,min=5" etc. — should demonstrate this.
  • WithOutputFormat not used — v2.WithOutputFormat[T]() auto-adds --output flag. Currently the format flag is manually defined in ListFlags/StatsFlags.
  • Email/URL/FilePath/HostPort types not shown — the library has these validated types but none are used.
  • GenerateManPageCommand not shown — the library can generate man pages.

Minor — Polish & Consistency

  • Channel-based mutex — TaskStore uses chan struct{} as a mutex. Clever but non-idiomatic. Should use sync.Mutex.
  • TestCLI_ConfigDefaults is a stub — the test body is _ = cfg. Should test actual defaults.
  • Seed data in tests — every test gets seeded data via newTestCLI, but some tests (empty list) need unseeded stores. The pattern works but the seed call in newTestCLI could be optional.
