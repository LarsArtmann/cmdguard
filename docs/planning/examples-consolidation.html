cmdguard Examples Consolidation Plan

Date: 2026-05-31 · Status: Ready to Execute

The Goal

Replace 15 scattered, shallow examples with ONE superb example — a production-grade task manager CLI that demonstrates every single cmdguard feature in a cohesive, realistic application.

Current State: Why This Needs Fixing

✗ Problems with Current Examples
  • 15 directories — cognitive overload, users don't know where to start
  • Most examples are trivial toys (basic, counting, env-tags print one line)
  • Heavy duplication: 5+ examples show NewCLI+NewCommand identically
  • Inconsistent patterns: some use internal.Execute, some use cli.ExecuteAndExit, some use panic
  • Tests are shallow — most only test creation or --help output
  • kitchen-sink is the closest to "good" but still named poorly and misses features
  • Each example requires its own go package, README, test boilerplate
✓ What a Single Superb Example Achieves
  • One entry point — zero decision paralysis
  • Users see a real-world CLI pattern they can copy-paste-adapt
  • Every feature demonstrated in context, not isolation
  • Comprehensive tests that serve as executable documentation
  • Maintenance burden: 1 package instead of 15
  • Feature coverage is auditable via feature matrix in README
  • Better first impression for new users evaluating the library

The Plan: One Superb Example

Design: "taskctl" — A Production Task Manager

A realistic CLI application that a developer would actually build. Every cmdguard feature is woven in naturally, not bolted on. The domain is simple enough to understand instantly but rich enough to demonstrate everything.

Architecture

examples/taskctl/
├── main.go              # Entry point: CLI construction, DI setup, command wiring
├── commands.go          # All command definitions (list, add, done, stats, config, inspect)
├── service.go           # TaskStore DI service with lifecycle hooks
├── types.go             # Domain types (Priority enum, Task, flags structs)
├── main_test.go         # Comprehensive integration tests
└── README.md            # Self-documenting: feature matrix, usage examples

Command Tree

taskctl                        # Root: config with env tags, signal handling, middleware
├── list                       # List tasks (OutputTable, multi-format, --format json/csv/yaml)
├── add                        # Add task (required flags, PreRunE validation, prompt tags)
├── done                       # Complete task (exit codes, PostRunE cleanup)
├── stats                      # Task statistics (OutputStyledTable, format flag)
├── inspect                    # Deep inspect a task (BranchingFlowContext, EditInEditor)
├── version                    # MustVersionCommand
├── health                     # HealthCheckWithContext, DI service verification
├── config                     # Show resolved config (env vars, config file, defaults)
│   └── edit                   # Edit config in $EDITOR
├── db                         # NewParentCommand — grouped subcommands
│   ├── migrate                # With DBFlags (env, force)
│   ├── seed                   # With DBFlags (shared flags via parent)
│   └── status                 # With DBFlags
└── _hidden                    # Hidden command (WithHidden)
    └── _deprecated            # Deprecated command (WithDeprecated)
