1. Deepen TypeHandler with Runtime Type Guards

Strong

Files: type_handler.go, type_handler_kinds.go, type_handler_custom.go, config_setfield.go

Problem: The TypeHandler interface erases all type information to any at the Parse/Default boundary. A tag typo produces a runtime panic instead of a registration-time error. DefaultFunc in all kind handlers silently returns zero on invalid defaults.

Solution: Add TargetType() reflect.Type to TypeHandler. Verify return type matches before returning. Return errors in DefaultFunc instead of swallowing.

Benefits: Catches misconfiguration at registration-time, not runtime. Locality: type safety logic concentrated in one seam.

Before 
dispatchParse(tag, value) -> any
  | (no type check)
setField(cfg, fieldName, any) -> panic
After 
dispatchParse(tag, value) -> (any, error)
  | verify result.Type() == handler.TargetType()
setField(cfg, fieldName, typed) -> clean error

2. Deepen MergeConfigs: Replace IsZero Sentinel

Strong

Files: config.go

Problem: MergeConfigs uses IsZero() as "field not set" sentinel. Legitimate zero values (false, 0, 0s) are silently overwritten — data loss for a config library.

Solution: Track explicitly-set fields via a map built during flag parsing. Only merge fields the user explicitly set.

3. Extract Flag System into Deep Module

Worth Exploring

Files: flags.go, flags_parse.go, flags_validate.go, flag_helpers.go, config_parsing.go, config_setfield.go, config_file.go, type_handler*.go

Problem: Flag system spread across 10 files in flat package. CLI[T] must know about FlagRegistry, FlagTag, TypeHandler, ConfigFileLoader, and setField separately.

Solution: Create FlagSystem facade: RegisterFlags(cfg), ParseFlags(cmd, args), ValidateFlags(cmd). CLI[T] only talks to FlagSystem.

4. Eliminate Global Singletons

Strong

Files: type_handler.go, flags_validate.go

Problem: Three mutable package-level singletons. Clone-once semantics are confusing. Tests that modify globals pollute other tests.

Solution: Make NewFlagRegistry accept RegistryConfig. Remove package-level RegisterTypeHandler()/RegisterValidator(). Provide DefaultRegistryConfig() function.

5. Split errors.go into Domain-Specific Files

Worth Exploring

Files: errors.go (376 lines, 51 sentinels)

Problem: 51 sentinels in one var block is a god-object. Finding the right error requires scrolling 190 lines.

Solution: Split into errors_command.go, errors_flags.go, errors_config.go, errors_di.go, errors_output.go. Keep shared types in errors.go.

6. Unify Field Value Formatting

Worth Exploring

Files: config_file.go, flags_validate.go

Problem: Two near-identical reflection-to-string converters with subtly different behavior. DRY violation causing split-brain formatting.

Solution: Extract single formatFieldValue into flag_helpers.go. Both callers use it.

Top Recommendation

Start with Candidate 1 (TypeHandler type guards) — highest impact, lowest effort. Follow with Candidate 4 (eliminate global singletons) for test isolation, then Candidate 2 (MergeConfigs fix) for data correctness.
