01Findings

Dead Must* constructors violated the zero-panic contract

MustNewCommand / MustNewParentCommand were the only panic() calls in non-test library code, had zero callers, and directly contradicted AGENTS.md Gotcha #38 ("All Must* functions removed in v2.5.0"). Removed.

Dead FlowContext interface

Declared in flow_context_access.go but never implemented, never used as a constraint, never referenced outside its own declaration. Its Branch(...) (*Scope,...) method existed nowhere. Removed.

Split brain: two FEATURES.md files

Root FEATURES.md (current, v2.7.0) coexisted with docs/FEATURES.md (stale, v2.4.0). The stale copy diverged on status legend, version, and feature list. Removed the stale duplicate.

Misleading dead conditional in Execute()

Both branches of if cli.writeFormattedError(execErr) returned an identical wrapped error, making the conditional meaningless. Simplified to a single unconditional return; the JSON-error side effect is now an explicit comment.

Length validators now count characters, not bytes

validateMinLen/validateMaxLen used len(val) (bytes) but reported "characters". Multi-byte UTF-8 input was miscounted. Switched to utf8.RuneCountInString and added a regression test.

03Strengths

+
Layered zero-panic guarantee safeProvide recovers provider panics into errors; RecoveryMiddleware recovers handler panics with stack traces. Two independent nets make the contract robust.
+
"Parse, don't validate" value types Port, Email, URL, Duration, HostPort, Enum are opaque structs with unexported fields, constructible only via Parse*. Invalid states are unrepresentable at compile time.
+
Copy-on-write registries typeRegistry/validatorRegistry share global maps via lazy clone, cutting NewCLI cost ~48% while keeping per-instance overrides safe.
+
Centralized, chainable error model 40+ sentinels across domain files, all wrapped with %w so errors.Is works end-to-end. Typed wrappers (CommandError, FlagError, …) add context without losing the chain.
+
Modern Go throughout iter.Seq zero-alloc iterators, errors.AsType[T], slices/maps, sync.OnceValue caching, generics-native DI (Provide[T]).

04Open Recommendations (not auto-fixed)

ErrServiceNotFound — exported but unreachable

The sentinel is declared, unit-tested, and listed in the JSON error classifier, but no production code path returns it. It is part of the public API, so removing it would be breaking. Decision deferred to maintainer: either wire it into a real path (e.g. a typed Invoke wrapper) or document it as a consumer-facing sentinel.

AGENTS.md claims drift

Header still says "0 lint issues" (was 2 before this review; now genuinely 0 again). Gotcha #14 claims the sync.Map regex cache "must not run in parallel" — sync.Map is concurrency-safe, so the caveat is misleading. Both are doc-only fixes.

int64 / uint64 flag precision

All integer kinds route through pflag's 32-bit Int/Uint registration, so an int64 or uint64 config field cannot hold values > 2³¹−1. Registering dedicated Int64/Uint64 handlers for those kinds would remove the silent truncation. Low customer impact today; worth a follow-up.

Test-helper file naming clarity

Three files differ by a single underscore and a misleading name: test_helpers_test.go (internal), testhelpers_test.go (external v2_test), and helpers_test.go (which actually contains real tests like TestLogLevel, not just helpers). Renaming/consolidating would improve navigability — purely cosmetic, deferred to avoid churn.

Minor type-strictness opportunities (design notes)

Port stores an int where uint16 would make the 0–65535 invariant unrepresentable-violating (matches the architect checklist's "use uints"). Arg-count options (WithExactArgs, …) take int and validate non-negative at runtime; uint would push that to compile time. Both conflict slightly with cobra/pflag's int APIs, so they are tradeoffs, not defects.

Verdict No action-blocking defects remain. The codebase is production-grade: strong types, defense-in-depth against panics, comprehensive tests (86.5%, race-clean), and zero lint issues. The remaining items are polish and doc-sync work.
