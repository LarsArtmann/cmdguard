00Summary

cmdguard’s adoption surfaces are already the most mature in the fleet. The corpus records evaluation-by-docs working exactly as designed: one consumer ran its entire cmdguard audit from README and SKILL.md line citations alone and never opened library source; no review reports a hallucinated cmdguard API name. The remaining work is convergence, not construction: three verified places where README, SKILL.md, and source tell different stories about the same fact; the recurring “capability invisible → consumer hand-rolls it” pattern; an agent story that is marketed but never walked end-to-end; and near-zero cross-skill pollination across the 54-skill fleet.

The bottom line The surfaces that exist are good — the declines recorded in the corpus are fit-based (audiblesync: “4 flags, 0 subcommands, 0 config files”), not doc-based. The work left is: one reference per fact (validate rules, tag vocabulary, sentinel counts), capabilities sold as one-line wins, skill numbers derived instead of hand-counted, and the agent loop demonstrated once in public. Every finding below is Low-to-Medium effort; several are under an hour.

◆What the fleet already rates

Evidence first, because the improvement list only lands if it starts from what demonstrably works.

+
Docs-as-spec is real, not aspirational audiblesync’s cmdguard review (v5.1.0, verdict HOLD) cites SKILL.md by line ranges (6–10, 29–36, 52–75, 82–99, 101–122, 141–150) and README ranges (60–79, 91–123, 535–559) — zero source reads, and the decision (“4 flags, 0 subcommands, 0 config files”) is reachable purely from docs. That is the same consumer whose go-appkit audit set the line-citable gold standard.
+
The claims table is the fleet’s anti-hallucination device SKILL.md’s Verification-status table (claim / status / source+date per row) is precisely the discipline the go-appkit corpus demanded after its one API-name hallucination (“CORRECTION OF RECORD: WithEvaluationHook does NOT exist in the library”). No cmdguard review needed a correction of record — the device shipped before the failure mode could.
+
The error reference cannot drift docs/ERROR_REFERENCE.md states its own guarantee in line 3: “The sentinel table is generated from source and drift-guarded by a test.” Generated references are the endgame the rest of this report pushes the other surfaces toward.
+
Migration is a product, not a page Four migration documents (from Cobra, v2→v3, v3→v4, v4→v5) plus a mechanical codemod (docs/migration_v4_v5/codemod.sh) and an explicit retired-line policy (v4 frozen at v4.3.1 on release/v4). No sibling library ships a codemod; the corpus treats this as a stated differentiator.
+
Marketing surfaces exist and agree A real Astro website (21 guides, quick-start, installation), a README trinity comparison table, and feature data that carries the same claim on every surface: type-safe flags + DI + zero-panic error contract, batteries on by default. MIT license stated plainly — which matters, because the corpus shows evaluators flag license unprompted.
+
The agent contract is real and documented describe prints a versioned JSON contract (types, defaults, env vars, enums, required flags, inheritance), Describe() / WriteDescription() expose it programmatically, the machine-contract guide exists, and the schema sub-module emits JSON Schema 2020-12. The pieces are shipped — finding 9 is about assembling them into one demonstrated loop.

01Findings

Ten findings in three groups — Docs, Marketing, AI-Skills — ordered by impact. Each names the exact files and lines so every claim is replayable.

Docs · High impact

1. The validate-rule registry is documented nowhere consumer-facing

pkg/cmdguard/v5/flags_validate.go:58-67 · README.md:439 · .agents/skills/cmdguard/SKILL.md:250

The source registers ten named rules: email, url, minlen, maxlen, min, max, dmin, dmax, regex, nonempty. The README shows a single example (validate:"email,min=5") and no rule list. The SKILL.md tag table documents different syntax (validate:"min=1,max=100") and describes min/max as “length on strings, numeric otherwise” — but the source splits string length into separate minlen/maxlen rules. Two surfaces, two half-stories; the only complete registry lives in unexported source. This is the quotaboard lesson verbatim: when docs do not carry the capability surface, evaluators read source and lose trust in the docs they did read.

Fix One canonical table — rule / parameter / applies-to / resulting error — in the README tag section and the website type-safe-flags guide; SKILL.md links to it instead of restating. Under an hour.
AI-Skills · High impact

2. The skill’s own verification table contradicts itself

.agents/skills/cmdguard/SKILL.md:43 vs SKILL.md:288

Line 43: “59 exported sentinel error vars.” Line 288: “62 documented sentinel errors.” Both hand-written, mutually exclusive, both in the same file whose crown jewel is a table whose entire purpose is that every claim carries a source. An agent quoting the skill inherits whichever number it reads first — and the ChastityAPI incident in the go-appkit corpus shows exactly how a single unverified number in an otherwise excellent document becomes the citation that propagates.

Fix Never hand-count. Derive sentinel counts from docs/ERROR_REFERENCE.md (already source-generated) or a one-line rg at write time, and only write a count row when the Source column carries the runnable command that produced it.
Docs · Medium impact

3. README and SKILL.md disagree on the tag vocabulary

README.md:431-443 (11 tags) vs SKILL.md:239-253 (13 tags)

The README’s Flag Tags Reference lists 11 tags. The SKILL.md lists 13 — adding prompt:"Question?" (which the README’s own Features table sells at line 233) and secret:"true" (sold in the config-explain prose at line 559). A consumer building a prompt or a redacted field from the README reference table concludes the tags do not exist. The fleet’s contract-string rule is explicit: when two surfaces carry the same reference, they drift, and the drift surfaces in a consumer audit.

Fix Make the README table the 13-tag superset and have every other surface (SKILL.md, website guides, schema docs) point at it as the single reference.
Docs · Medium impact

4. Released-vs-pinned gating is left for the consumer to reconstruct

io-surface review (v4.2.1 pin) · CHANGELOG.md:8 ([Unreleased])

io-surface’s reviewer had to flag which features were unreleased at their pin — strict config keys, config explain, the stable error_code envelope — and did it by reading the repo, because no doc says “since vX”. The go-appkit corpus shows this tax compounding: quotaboard burned an audit on an unreleased default-stack change, PapDashboard could not adopt master-only submodule features at all, and three reviews needed mid-audit refresh banners when a new tag landed. cmdguard’s CHANGELOG discipline is right; the README sells HEAD unversioned.

Fix Version-annotate capabilities that post-date the widely-pinned baseline (v5.0.0) — a “since” column in the features table, or a changelog link per feature row.
Docs · Medium impact

5. Coverage claims are hand-maintained in two places

README.md:8 (static badge) · README.md:242 (feature row)

A static “coverage-89.3%” badge plus a “Verified… 89.3% core coverage” feature row, both hand-synced. The stale-claim pattern the corpus keeps catching (quotaboard’s “field does not exist at the pinned version”, the 59-vs-62 split above) starts exactly here: a number in prose that no test guards.

Fix Generate the badge from the CI coverage workflow, and let the Verified feature row link the CI run instead of restating a number.
Marketing · High impact

6. The one-line-wins section that converts does not exist

README.md (no such section) · pattern evidence: io-surface, PapDashboard, quotaboard, media-atlas reviews

The single most repeated conversion pitch in the 41-review corpus: consumers hand-roll exactly what the library already owns, one capability at a time, and every fix is “one line”. io-surface — a 100/100 cmdguard adopter — hand-rolled its exit-code contract (0/1/2) and a custom version command that overrides cmdguard’s auto-registered one; both are shipped features. PapDashboard’s go-appkit audit found ~400 lines of hand-rolled security middleware duplicating a submodule; quotaboard and media-atlas list the same one-liners audit after audit. cmdguard’s README lists features as a table; it never says “delete your hand-rolled X”. 

## Replace your hand-rolled...
- Error printing + exit code  -> cli.ExecuteAndExit(ctx)      # was: fmt.Fprintln + os.Exit ladder
- version command             -> automatic (WithCLIVersion)   # was: a hand-rolled cobra command
- doctor / health checks      -> automatic (batteries)        # was: ad-hoc self-check command
- "did you mean?" suggestions -> automatic                    # was: nothing, or a TODO
Fix A “Replace your hand-rolled” README section: each row a 3-line before/after, ordered by lines-deleted. This is the highest-conversion section the corpus knows how to ask for.
Marketing · Medium impact

7. Claims are strong but ship without verification recipes

README.md:17 (“the only Go CLI framework that unifies…”) · README.md:29-43 (trinity table)

“The only framework that…” and a nine-row comparison table are exactly the claims an agent consumer re-verifies before trusting the rest. The go-appkit corpus rewarded library claims that arrive with their proof (go-taskqueue’s audit accepted the README because every row replayed in one command), and its one API-name hallucination shows what an unreplayable claim costs. All 18 cmdguard reviews contradict none of the claims — the gap is that the proof lives in tests an evaluator must find unaided.

Fix A “How to verify” block under the trinity table: one runnable line per row (constructor validation = the duplicate-name probe; zero-panics = rg "Must|panic" pkg/; describe = the taskctl describe output). Marketing that ships its own replay commands gets cited as a spec.
AI-Skills · High impact

8. Cross-skill pollination is where adoption happens — cmdguard is barely in the graph

/home/lars/projects/SKILLS/*/SKILL.md — 3 of 54 mention cmdguard

The cleanest funnel evidence in the whole corpus is profileagent’s go-appkit review: a skeleton repo that never opened a README adopted a mental model, a trigger condition, and a named recipe purely because a sibling skill carried them (“the go-cqrs-lite skill points at its cqrs EventService recipe”). audiblesync ranked a sibling skill’s option before appkit’s own docs. Today exactly three fleet skills mention cmdguard — stack-selection, buildflow, nix-private-go-repos — as tooling facts, not adoption recipes. No sibling skill hands a CLI question to cmdguard the way go-cqrs-lite’s skill hands a lifecycle question to cqrs.

Fix A reciprocity pass: add named cmdguard entries to sibling skills’ related-tools/recipe sections (“need a CLI for the admin tool? cmdguard NewApp recipe”), and give cmdguard’s own SKILL.md a works-with section pairing it with the service stack (go-appkit service + cmdguard ops CLI; taskctl as the flagship pattern). Recipes with names travel.
AI-Skills · Medium impact

9. The agent loop is marketed but never walked end-to-end

website guides/machine-contract.mdx · docs/ERROR_REFERENCE.md (Machine error codes)

Every piece is shipped and documented separately: the versioned describe JSON, stable error_code, actionable hint, human Hint: lines, the JSON Schema emitter. No single document walks the loop an agent actually runs: discover the CLI via describe → invoke → hit a classified error → read error_code + hint → recover. The corpus’s marketing lesson says the walkthrough IS the feature — cqrs-htmx’s mechanical sweep surfaced “godoc examples” as a capability unprompted, and profileagent converted on a named recipe.

Fix One end-to-end walkthrough in machine-contract.mdx: describe output → invoke → JSON error envelope with error_code+hint → recovery decision; cross-link schema.FromCLI as the tooling path. Optionally an MCP-facing recipe — “agents drive your CLI without scraping --help” deserves its demonstration.
Marketing · Low impact

10. Two surfaces lead with two headlines

README.md:15 vs website HeroSection.astro:77-84

The README leads with construction-time catches (“catches missing handlers, duplicate commands, and invalid flags at construction — not at 2am in production”); the website hero leads with breadth (“From flags to shutdown, type-safe.”). Both true, trinity subtitle matches — but an evaluator gets a different “what is this” on the first line of each surface, and the corpus shows evaluators quote the first line as the positioning when they record a verdict.

Fix Tier deliberately: README = why-switch (the 2am construction argument), website = what-it-is (type-safe to shutdown), each linking the other. Decide once, write it down, don’t drift.

02What the converged state looks like

Every finding reduces to one rule the fleet already learned from go-appkit’s audits: one fact, one home; every other surface points at it. 

Single-source targets
  tag vocabulary        -> README Flag Tags Reference (13-tag superset)
  validate rules        -> new canonical table (10 rules, one row each)
  sentinel error count  -> docs/ERROR_REFERENCE.md (already generated; derive, never hand-count)
  coverage number       -> CI badge artifact (README links, never restates)
  feature versions      -> "since" column sourced from CHANGELOG sections
  positioning lines     -> one tiering decision, recorded once

Cross-surface plumbing
  SKILL.md              -> links the references above; claims-table rows keep runnable Sources
  website guides        -> mirror the references via build-time include, not copy-paste
  sibling skills        -> named cmdguard recipes (the profileagent funnel, pointed at cmdguard)
  machine-contract.mdx  -> one walked agent loop: describe -> invoke -> error_code -> recover
Sequencing Week one: findings 1, 2, 3, 5 (all Low effort — they close every verified drift site). Week two: findings 6 and 7 (the README conversion sections). Then findings 8 and 9 (the skill graph and the agent walkthrough). Finding 10 is a decision, not a task — make it whenever, write it down.
