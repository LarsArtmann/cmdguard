00Summary

The dependency upgrade itself was well-executed: all tests pass, 0 lint issues, 86.6% coverage (up from 86.5%), and the refactoring to use v0.3.0's Plugin-level methods eliminated 63 lines of redundant adapter code. However, I created 3 split brains by updating format lists in AGENTS.md and CHANGELOG.md but missing docs/API.md, examples/taskctl/README.md, and examples/taskctl/main.go. These were caught and fixed in a follow-up commit.

The bottom line The upgrade is solid and complete. All split brains have been resolved. One security item (Go 1.26.4 stdlib CVEs) is genuinely blocked on nixpkgs packaging and is documented in CHANGELOG + TODO_LIST. No ghost systems remain.

01Findings

Critical · Split Brain · Fixed

3 stale format lists created by the upgrade

docs/API.md:403, examples/taskctl/README.md:62, examples/taskctl/main.go:114-115

After adding 4 new audit log formats (d2, plantuml, tree, htmltree), I updated AGENTS.md and CHANGELOG.md to say "11 formats" but forgot to update 3 other files that enumerate the format list. This created a split brain: the code and some docs said 11, but API.md and the example still said 7.

Root cause: I grepped for specific patterns ("7 formats", "v0.1.0") instead of grepping for the actual format names ("html.*json.*ndjson"). The format lists were written differently in each file, so my pattern missed them.

Fixed All 3 files updated in commit 0cc99a9. Also documented the v0.3.0 ExportToTable 16-sub-format option in API.md.
Important · Security · Deferred

3 stdlib CVEs in Go 1.26.3 (GO-2026-5037/5038/5039)

govulncheck output · Fixed in Go 1.26.4 · nixpkgs only has 1.26.3

GO-2026-5037 (inefficient hostname parsing in crypto/x509) is reachable via cmdguard.ExitError.Error. The other two (net/textproto, mime) are imported but not called by cmdguard code.

I initially bumped go.mod to go 1.26.4 which triggered the GOTOOLCHAIN auto-download, but this broke nix flake check because the nix sandbox cannot reach proxy.golang.org. Even nixpkgs-unstable only packages Go 1.26.3. The bump is genuinely blocked.

Status Documented in CHANGELOG with a Security section. Should be re-checked when nixpkgs updates go_1_26. Consumers building with Go 1.26.4+ are not affected.
Minor · Ghost System · Documented

v0.3.0 Table export (16 sub-formats) not wired into AuditLogFormat enum

auditlog v0.3.0: Plugin.ExportToTable / Plugin.WriteTable

The table export in auditlog v0.3.0 renders a service summary table in any of 16 go-output formats (table, json, csv, tsv, markdown, xml, d2, yaml, html, tree, mermaid, dot, jsonl, asciidoc, toml, plantuml). This is a different view from the per-format exports (which produce full audit reports with events).

It's not a ghost system — users access it via cli.AuditLog().ExportToTable(path, format, opts) since cli.AuditLog() returns the raw plugin. But it's not in the AuditLogFormat enum because its signature (format output.Format, opts output.RenderOptions) doesn't fit the existing auditLogExporter registry pattern.

Resolved Documented the ExportToTable option in docs/API.md so users know it exists. No code change needed — the plugin accessor already exposes it.
Minor · Pre-existing · Not my scope

122+ gopls infertypeargs warnings across test files

cli_*_test.go files throughout pkg/cmdguard/v2/

These are pre-existing "unnecessary type arguments" warnings (e.g. v2.NewCLI[testCLIConfig] where Go 1.26 can infer the type). They are cosmetic and predate this work. Not fixing them because the rules say "Don't fix unrelated bugs" — but noting them here for visibility.

Minor · Pre-existing · Not my scope

auditLogExporterRegistry() allocates a map per call

pkg/cmdguard/v2/auditlog.go:48

The registry function returns a new map on every call (to satisfy gochecknoglobals). The comment says "per-call allocation is negligible (export runs once)". This is true but could be cached with sync.OnceValue if it ever becomes hot. Not changing now — YAGNI.

03Self-Review Answers

1. What did you forget?

I forgot to grep for the format name strings themselves. I searched for "7 formats" and "v0.1.0" but the stale references used inline lists like "html/json/ndjson/csv/tsv/mermaid/dot". After the self-review prompt, I searched for "html.*json.*ndjson" and found all 3 split brains immediately.

2. What is something stupid that we do anyway?

The taskctl binary (24MB) sits in the repo root as a local build artifact. It's gitignored so it's not tracked, but it clutters ls. Not a real problem — just noise.

3. What could you have done better?

After any change to a public API surface (adding enum values), I should grep for all places that enumerate or list those values — not just the files I happen to know about. A regex like rg "html.*json.*ndjson" would have caught all 3 stale references in one shot.

4. What could you still improve?

The table export from v0.3.0 is powerful but doesn't fit the current registry pattern. A future enhancement could add a separate ExportAuditLogTable[T](cli, path, format, opts) function for the 16-sub-format service summary. But this is YAGNI until someone asks for it.

5. Did you lie to me?

No. I said "All green" after the initial upgrade, which was true for build/test/lint/format. But I hadn't checked docs/API.md or examples/taskctl for stale format lists — so "all green" was incomplete. The split brains existed for about 10 minutes before the self-review caught them.

6. How can we be less stupid?

Add a CI check that validates documentation consistency: if the code exports N format constants, grep the docs and examples for format lists and verify they match. This would have caught the split brain automatically.

7. Ghost systems?

The table export (16 sub-formats) was initially a ghost — available in the dependency but not discoverable from cmdguard's docs. Now documented in API.md. No code integration needed since cli.AuditLog() already returns the raw plugin.

8. Scope creep?

No. The dependency upgrade was well-scoped. The refactoring (removing adapters, adding formats) was a direct consequence of the upgrade, not scope creep.

9. Did we remove something useful?

No. The 5 removed wrapper functions (exportMermaidReportToFile, writeMermaidReport, etc.) were genuinely redundant after v0.2.0 added Plugin-level methods. The removed code was strictly worse than the upstream API.

10. Split brains?

Yes — 3 of them, all created by the upgrade, all now fixed:

  • docs/API.md:403 — format comment said 7, now says 11
  • examples/taskctl/README.md:62 — format list said 7, now says 11
  • examples/taskctl/main.go:114-115 — comment listed 7, now lists 11

11. How are we doing on tests?

Good. The parametric test loop (TestExportAuditLog) automatically covers all 11 formats for both writer and file exports. Coverage went from 86.5% to 86.6%. All tests pass with race detection. Could improve by adding content validation for diagram formats (e.g., verify d2 output contains shape:), but the current "non-empty output" check is sufficient for CI.
