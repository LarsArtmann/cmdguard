Headline: clean codebase, three names worth renaming

No name lies about behavior. No Impl, no Abstract, no I prefixes. Constructors, functional options, and sentinels follow Go convention consistently. The three High-severity findings below are the only names where a newcomer would have to read the definition to understand what the type does — everything else reads from the call site.

03Honesty Issues (Critical)

None found.

No function mutates state while named getX; no euphemisms (sanitize for delete); no misleading scope. Every getter (cli.Name(), cli.Config(), email.Domain()) is a pure query. Every command verb (Add, Done, Shutdown) does what it says.

04Clarity Issues (High)

High

TypeHandler interface — “Handler” is a trash-can name

pkg/cmdguard/v3/type_handler.go:12-17

The interface has three methods: Register, Parse, Default. It does not “handle” anything in the usual event-handler sense; it adapts a reflect.Type to the flag system by providing parse/default/register behavior. Every implementor is a codec for a specific type.

Better name TypeCodec — parallels encoding/json.Marshaler / TextMarshaler, both of which bundle parse+format under one contract. The functional adapter becomes TypeCodecFunc, and the registry helper stays RegisterTypeCodec. If backward compatibility matters, deprecate TypeHandler as an alias and ship the new name alongside.
High

StringSliceContains is a duplicate name for ContainsString

pkg/testutil/panic_test_helpers.go:107-114

Two exported functions do the same thing. The doc comment even admits it: "StringSliceContains is an alias for ContainsString for better readability." Two names for one concept is the textbook split-brain: a reader who sees both in different files wonders if they differ. (Both also just wrap slices.Contains.)

Fix Delete one. Keep slices.Contains directly at call sites; if a testutil helper is wanted, keep ContainsString and remove the alias. Better yet, migrate callers to slices.Contains and remove both — the stdlib name is already the right one.
High

doPanicTest uses the vague do prefix

pkg/testutil/panic_test_helpers.go:132-147

do says nothing. The function returns true if fn panicked. The exported wrappers (AssertPanics, ExpectPanics, AssertDoesNotPanic) are well named; only the private helper has the smell.

Better name panics(fn) bool — reads naturally at call sites: if panics(fn) { ... }. Matches the bool-as- question convention.

05Domain Alignment (Medium)

Medium

CommandInfo — mild “Info” suffix

pkg/cmdguard/v3/middleware.go:40-45

The struct carries metadata about an in-progress command (Name, FullPath, Phase, HasRunE) for middleware. Info is one of the “I contain stuff” anti-words, but the alternative CommandMeta is longer and the current name is idiomatic. Worth a rename only if other *Info types start appearing.

Optional Rename to CommandMeta if the team prefers; otherwise accept and document the convention so the suffix does not proliferate.
Medium

HuhRunner leaks the implementation library

prompts/prompts.go

The unexported struct embeds huh/v2 directly. The name is fine for an unexported type, but if it ever becomes exported, prefer PromptRunner (matching the interface it implements) over naming it after the library.

Accept as-is Unexported; no rename needed. Flag for review if exported later.

06Consistency Issues

No verb-tense or synonym drift detected.

CRUD verbs on TaskStore are consistent (Add/Get/List/Done/Shutdown). Constructors all use New* (NewCLI, NewCommand, NewParentCommand, NewScope, NewManPage, NewTaskStore). Functional options all use With* consistently (WithShort, WithLong, WithExample, WithAuditLog, etc.). Iterator methods share the *Seq suffix (TagsSeq, FlagNamesSeq, PathSeq, ChildrenSeq).

07Implementation Leakage

None detected.

No Impl suffix. No Abstract or Base prefixes. No I prefix on interfaces (Go convention). The only mildly leaky name is HuhRunner (above), and it is unexported. The DI Scope is named for its role, not for samber/do. Flag types (Enum, Port, etc.) are named for the domain concept they brand, not for pflag.

08Strengths to Preserve

+
Branded primitive types Email, Port, URL, FilePath, HostPort, Duration — each is a named type with a validating constructor. The domain language IS the type system.
+
Consistent Err* sentinels 40+ sentinel errors all use Err prefix, all chainable via errors.Is. No ...Error suffix, no mixed conventions.
+
Question-shaped booleans NoColor() bool, Valid() bool, HasRunE — all read as yes/no questions. No isNotEnabled-style inversions.
+
Domain verbs in TaskStore Done(id) over UpdateStatus(id, "done"); Seed/Stats/IDs are short, declarative, and use the domain vocabulary.
+
Role-named DI type Scope (not DoInjector or DIContainer) — named for its architectural role, not for the library that implements it.
+
Two-letter type params CLI[T], Command[T,F] — single-letter type params are the one accepted exception to the no-abbreviation rule (math context, Go convention).
